# Development Conventions

## Commit Style
Concise messages describing WHAT changed — no narrative, no emojis.
Example: `Add profiler decorator library` not `Working on profiling stuff`.

## Code Quality
- Type hints on all public functions and methods
- Google-style docstrings (Args/Returns sections)
- No emojis or unnatural language in comments/docstrings
- Professional tone throughout

## Linting & Formatting
- ruff for linting: `ruff check .`
- mypy for type checking: `mypy backend/ tests/ profiler.py`
- Fix lint errors before committing

## Testing
- pytest coverage target ≥80%
- Tests in tests/ directory
- Each module has corresponding test file

## Structure
backend/ — FastAPI + SQLAlchemy + SQLite
frontend/ — HTML/CSS/JS with Canvas API for flame graphs
tests/ — pytest suite
profiler.py — importable decorator library
docker-compose.yml — local development setup

## Private Repos Only
All repositories remain private unless explicitly approved for public.
